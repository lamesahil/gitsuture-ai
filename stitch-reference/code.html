ARCHITECTURE & LIFECYCLE

Autonomous repair in four structured steps.

GitSuture isolates pull request failures and verifies proposed patches before updating branches.

01 webhook

Detect

GitHub webhook catches failing PR check suites in real time (< 120ms). GitSuture intercepts the event without altering CI queue precedence.

Hook latency: ~45ms
02 account_tree

Diagnose

GitSuture spins up an ephemeral local container, isolates stack traces, and extracts the AST call graph to pinpoint the exact broken assertion.

AST-guided analysis
03 healing

Repair

Context-constrained patch generation targeting the relevant error scope without touching unrelated files or dependencies.

Gemini Models
04 task_alt

Verify

Patch is applied inside the isolated sandbox and the test suite is rerun. Only 100% verified patches update the branch and re-trigger green CI.

Gatekeeper: Tests verified before commit
DESIGNED FOR SURGICAL PRECISION

Why engineering teams trust GitSuture in production.

terminal

Sandboxed Execution

Untrusted PR code runs strictly inside an isolated rootless Docker sandbox. Enforced with resource boundaries (cpu: 2, mem: 2GiB) and completely disabled outbound networking (--net none).

troubleshoot

Context-Aware Repair

GitSuture uses call-graph stack analysis to provide the AI model only the precise AST context required to solve the error trace, eliminating broad extraneous code edits and unnecessary refactors.

verified_user

Verified Healing

A generated patch is never pushed to GitHub unless the repaired workspace passes the entire test suite inside the reproduction container. Tests verified before commit to your repository.

lock_clock

Controlled Repair Loop

Controlled repair loop with strict bounded attempt limits (max 3 loops). If an ambiguous or systemic architecture change is required, GitSuture steps aside gracefully and leaves diagnostic breadcrumbs.
